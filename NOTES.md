# NEON DUEL («Танчики на двоих»): разбор исходного кода

Разбор сделан 2026-10-26 по архиву `two-player-html-game.zip` (лежит в файлах проекта). С 2026-10-26 код лежит в репозитории vaul17rep/tanchiki (первый коммит = нетронутый архив). Задача заметок: чтобы к исходной версии кода не нужно было возвращаться.

## 1. Что это за игра

Дуэль двух танков на одной клавиатуре, вид сверху, неоновый стиль. Пули рикошетят от стен и препятствий, на арене появляются бонусы. Матч до 3 выигранных раундов, раунд 60 секунд, после таймаута при равных HP включается «внезапная смерть». Весь текст на русском. Название в интерфейсе: **NEON DUEL**.

## 2. Стек и файлы

React 19 + TypeScript 5.9 + Vite 7 + Tailwind CSS 4. Графика арены на Canvas 2D, интерфейс (меню, HUD, оверлеи) на React поверх канваса. Звук синтезируется через WebAudio, файлов ресурсов нет вообще (ни картинок, ни звуков).

| Файл | Строк | Что внутри |
|---|---|---|
| `src/game/engine.ts` | 1170 | Весь игровой движок: класс `Game` (цикл, ввод, физика, бонусы, частицы, рендер, снимок для UI) |
| `src/App.tsx` | 578 | Меню, HUD, оверлеи (отсчёт, «БОЙ!», конец раунда, финал, пауза), хоткеи M/R, автопауза |
| `src/game/audio.ts` | 129 | `SoundEngine`: синтез звуков (выстрел, рикошет, попадание, блок, взрыв, подбор, бипы, победа) |
| `src/index.css` | 231 | Tailwind + свои классы: неон, кейкапы, HP-слоты, анимации, CRT-сканлайны, виньетка |
| `src/main.tsx` | 10 | Точка входа, `<StrictMode>` |
| `src/utils/cn.ts` | 6 | `clsx` + `tailwind-merge` |
| `index.html` | 18 | Шрифты Russo One и Rubik с Google Fonts (внешний запрос!) |

Зависимости рантайма: react, react-dom, lucide-react (иконки), clsx, tailwind-merge. Имя пакета в `package.json` шаблонное: `react-vite-tailwind`.

## 3. Запуск и сборка

```
npm ci
npm run dev       # dev-сервер Vite
npm run build     # → dist/index.html
npm run preview
```

Проверено: `npm ci` и `tsc --noEmit` проходят без ошибок, `npm run build` даёт **один файл `dist/index.html`, 288 КБ (89 КБ в gzip)**, весь JS и CSS встроены. Файл открывается двойным кликом (`file://`), сервер не нужен. Единственное, что грузится из сети, это шрифты Google Fonts; без сети будут системные шрифты.

## 4. Архитектура

- `App` хранит экран (`menu` / `game`) и `gameKey`. При входе в игру или реванше `useEffect` создаёт `new Game(canvas, handleUi)`, при уходе вызывает `game.destroy()`. Реванш = пересоздание движка через смену `gameKey`.
- Движок не знает про React. Каждый кадр он вызывает `onUi(UiState)`. `App` делает `JSON.stringify` снимка и вызывает `setUi`, только если строка изменилась.
- `UiState`: фаза, пауза, отсчёт, секунды, флаги внезапной смерти, HP, счёт, номер раунда, победитель раунда/матча, активные эффекты (щит/темп/форсаж с остатком секунд).
- Обратная связь UI → движок: только `togglePause()` и `setPaused()`.
- Звук: синглтон `sound`; `sound.init()` создаёт AudioContext по первому действию пользователя (кнопка/Enter/M).

## 5. Игровой цикл и фазы

`requestAnimationFrame`, шаг `dtReal` ограничен 33 мс (при лагах игра замедляется, а не «прыгает»). Есть `timeScale` для slow-mo: при убийстве ставится 0.22 и плавно возвращается к 1. Внутренние часы `clock` (мс) идут только вне паузы и с учётом slow-mo; все таймеры (бонусы, щиты, фазы) считаются по ним.

Фазы: `countdown` (2.2 с, 3-2-1 с бипами) → `play` (+ надпись «БОЙ!» 0.75 с) → `roundover` (2.3 с) → снова `countdown` или `gameover` (конфетти, звук победы, кнопки «Реванш [R]» / «Меню»).

В фазе `play`: таймер раунда 60 с. По истечении побеждает тот, у кого больше HP; при равенстве включается внезапная смерть (таймер «— : —», любое попадание без щита выигрывает раунд). Танки и пули обновляются только в `play`, частицы всегда.

## 6. Управление

| | Движение | Огонь |
|---|---|---|
| Игрок 1 (голубой, слева) | W A S D | F или Space |
| Игрок 2 (розовый, справа) | Стрелки | Enter |

Общее: Esc или P пауза (не работает в `roundover`/`gameover`), M звук, R реванш только на финальном экране, Enter/Space в меню старт. Автопауза при скрытии вкладки. Ввод: `Set` нажатых `e.code`; для игровых клавиш вызывается `preventDefault`. Мыши, тача и геймпада нет.

Движение «аркадное 8-направленное»: нажатые клавиши задают направление, танк разгоняется (ускорение 1550 px/с², макс. 235 px/с, с форсажем 350) и поворачивает корпус к направлению движения (11 рад/с). Без ввода затухание `exp(-6.5·dt)`. Стреляет туда, куда смотрит корпус; отдельной башни нет.

## 7. Физика и коллизии

Логические координаты арены **1280×720**, рамка-стена 40 px. Канвас масштабируется под размер контейнера (16:9) с учётом devicePixelRatio (не больше 2), через `ResizeObserver`.

- **Танк**: круг радиуса 18. Стены: clamp координат. Препятствия: выталкивание круга из прямоугольника (`pushCircleOut`). Танк-танк: раздвигаются на половину перекрытия каждый.
- **Пуля**: круг радиуса 5, скорость 580 px/с, появляется в 31 px перед танком. Отражается от стен и прямоугольников (отражение по нормали к ближайшей точке). Умирает на 3-м отскоке (то есть живёт 2 рикошета) или через 7 с. До 5 своих пуль одновременно.
- **Перезарядка**: 0.42 с, с «Темпом» 0.16 с.
- **Самопопадание**: своя пуля безопасна только первые 350 мс и только пока не отскочила; после рикошета бьёт и владельца.
- **Попадание**: расстояние < 23. Щит поглощает одно попадание и исчезает. Иначе −1 HP, тряска, частицы; при 0 HP взрыв, slow-mo, раунд противнику.
- Туннелирования нет: при dt ≤ 33 мс пуля смещается максимум на 19 px, а самое тонкое препятствие 26 px (+10 на радиус).

**Карта** одна, зеркально-симметричная, 9 прямоугольников (центр 96×84, два малых блока 70×60, четыре горизонтальные планки 130×26, две вертикальные 26×120 у спавнов). Координаты в массиве `OBSTACLES`. Спавн: (118, 360) и (1162, 360).

## 8. Здоровье, счёт, бонусы

- HP: старт 3, лечение до 5 (HUD всегда рисует 5 слотов). Матч до 3 побед.
- Бонусы: первый через 5.5–6 с от начала раунда, далее каждые 4.2–6.5 с, на арене не больше 3, каждый живёт 9.5 с (последнюю четверть мигает). Спавн: не ближе 34 px к препятствиям, 150 px к танкам, 90 px к другим бонусам (60 попыток). Подбор по радиусу 32.

| Бонус | Цвет | Эффект |
|---|---|---|
| Ремкомплект (heal) | зелёный | +1 HP (до 5) |
| Щит (shield) | синий | блок одного попадания, до 7 с |
| Темп (rapid) | жёлтый | перезарядка 0.16 с, 6 с (в меню написано «x3», на деле ~x2.6) |
| Форсаж (speed) | фиолетовый | макс. скорость +49%, 6 с |

Веса: обычно heal 2/7, shield 2/7, rapid 2/7, speed 1/7. Во внезапной смерти лечения нет. Повторный подбор того же бонуса не суммирует время, а перезапускает его.

## 9. Графика и звук

Всё рисуется кодом: градиентный фон, «пыль», сетка, неоновые препятствия, бонусы с иконками, пули со шлейфом (additive blending), танк из примитивов (гусеницы, корпус, башня, ствол, откат), щит, метки P1/P2, частицы, всплывающий текст («-1», «БЛОК», «ЩИТ»…), тряска камеры. Поверх канваса CSS-сканлайны и виньетка. Много `shadowBlur`, это самое дорогое место рендера.

Звук: 9 процедурных эффектов в `audio.ts`, громкость мастер-канала 0.45. Музыки нет. Состояние mute не сохраняется между запусками.

## 10. Известные баги и слабые места

Проверено сборкой и запуском в Chromium (1366×650); остальное по чтению кода.

**Баги**
1. **Залипание клавиш.** Набор нажатых клавиш не очищается при потере фокуса окна (`blur`) или переключении вкладки. Если отпустить клавишу вне окна, танк продолжит ехать/стрелять после возврата.
2. **Выстрел в упор в стену бьёт по себе.** Пуля появляется в 31 px от центра танка; если танк прижат к стене или препятствию, пуля сразу «отскакивает», теряет защиту владельца и тут же попадает в него.
3. **Меню не помещается на невысоких экранах.** На 1366×650 обрезан верх (бейдж и заголовок), легенда бонусов ушла за низ; прокрутки нет (`overflow: hidden`). Проверено скриншотом.
4. **Одновременная гибель.** Если оба танка получают смертельное попадание в одном кадре, очко получает тот, кто обработан первым, а второй танк тоже «умирает» визуально.
5. Танк-танк: второй танк сдвигается без повторной проверки стен и препятствий, может на кадр залезть в препятствие.
6. Подпись «x3 скорострельность» не соответствует коду (~x2.6). У игрока 1 на экране управления не указан Space.
7. Константы дублируются: в `App.tsx` жёстко 5 слотов HP и 3 кружка побед, не связано с `CAP_HP` / `WIN_SCORE`.
8. На паузе продолжает двигаться фоновая «пыль» (мелочь).

**Ограничения для публикации**
- **Только клавиатура на одном устройстве.** Нет тача, геймпада, бота и онлайна. На телефоне игра неиграбельна; одиночный игрок играть не может.
- Внешние шрифты Google Fonts: на площадках с запретом внешних запросов (CSP) шрифты не загрузятся.
- Конфликт клавиш: Space стреляет за игрока 1, Enter за игрока 2; Esc в полноэкранном режиме браузера выходит из полноэкранного. Возможен «ghosting» дешёвых клавиатур при 6+ одновременных клавишах.
- Нет сохранений, настроек, локализации (только русский), SDK площадок, рекламы.
- `emitUi` каждый кадр делает `JSON.stringify`, нормально для 2 танков, но лишняя работа.

## 11. Идеи по доработке

Обязательное для площадок:
- Очистка ввода на `blur`/`visibilitychange`, фикс самопопадания (спавн пули внутри препятствия), адаптивное меню.
- Режим против бота (одиночная игра). Без него многие площадки и игроки отсеются.
- Управление для тача (два виртуальных джойстика на одном планшете) и геймпадов (Gamepad API).
- Шрифты положить локально (в сборку), локализация RU/EN.
- Интеграция SDK площадки (старт/пауза, реклама между матчами, сохранения).

Геймплей и контент:
- Несколько карт (сейчас массив `OBSTACLES` захардкожен), выбор длины матча, настройки.
- Отдельно вращающаяся башня или стрельба вбок, новые бонусы (тройной выстрел, мина, лазер).
- Музыка, сохранение mute, статистика матча.

Код: вынести настройки баланса в один конфиг, связать HUD с константами движка, разделить `engine.ts` на модули (физика, рендер, бонусы).

## 12. Что важно для публикации

- **Формат**: уже есть одиночный `index.html` на 288 КБ без ассетов. Для большинства площадок нужен zip с `index.html` в корне; для этого можно отключить singlefile или оставить как есть.
- **Размер** очень маленький, ограничения площадок не проблема.
- **Зависимости от платформы**: только браузер (Canvas 2D, WebAudio, ResizeObserver). Сеть нужна лишь для шрифтов.
- **Звук** стартует только после клика/клавиши (политика автозапуска браузеров), это уже соблюдено.
- **Пауза** при сворачивании уже есть, площадки обычно требуют также глушить звук: сейчас при автопаузе звук не выключается (но новых звуков на паузе нет).
- **Соотношение сторон** фиксировано 16:9, канвас вписывается в окно; для мобильных и портретного режима нужен отдельный лэйаут.
- Конкретные требования (SDK, реклама, модерация, иконки/скриншоты) зависят от выбранных площадок, их уточнить, когда площадки будут названы.

## 13. Доработки от 2026-10-26 (ветка claude/project-thread-vadmpd)

Разделы 1–12 описывают исходную версию. Что изменилось:

- **Режимы**: «2 игрока» и «против бота» (`src/game/bot.ts`, 3 уровня сложности). Бот ходит по сетке 20 px (BFS, 8 направлений), целится поворотом корпуса, уворачивается от пуль, на сложном стреляет с упреждением. Выстрел игрока 1 теперь только пробел (F убрана). Против бота игрок 1 управляется и WASD+пробел, и стрелками+Enter. После финала пробел или Enter ведут в меню, R даёт реванш.
- **Карты**: 6 штук в `src/game/maps.ts` (классика, колонны, лабиринт, ринг, коридор, крепость) и «случайная». Каждая задаёт свой размер поля (`bounds`) и точки спавна: ринг маленький, коридор длинный и узкий. Все зеркально-симметричны.
- **Настройки** (`src/settings.ts`): режим, сложность, карта, до скольких побед (3/5/7), язык, звук. Хранятся в localStorage (если доступен).
- **Исправлено**: залипание клавиш (очистка на blur/visibilitychange), выстрел в упор в стену больше не бьёт по себе (пуля неуязвима для владельца, пока не отлетела от его танка), одновременная гибель (второй удар в тот же кадр не считается), меню прокручивается, HUD берёт число слотов HP и побед из движка, подпись «×2,5», звук глушится на паузе и при скрытии вкладки.
- **Ввод**: геймпады (Gamepad API; 1-й → игрок 1, 2-й → игрок 2, Start = пауза), сенсорное управление (`src/components/TouchControls.tsx`: два стика и две кнопки огня для двоих на одном планшете, один стик и кнопка против бота). Включается на сенсорных устройствах.
- **Локализация**: `src/i18n.ts`, RU и EN. Язык: от площадки (параметр `lang` на VK Play), иначе из сохранённого или языка браузера.
- **Шрифты** Russo One и Rubik лежат в сборке (`@fontsource/*`), внешних запросов нет.
- **Площадки**: `src/platform/` (интерфейс `Platform`, сейчас `web` и `vkplay`, SDK пока не нужны). Сборка выбирается режимом Vite.

### Сборки

```
npm run build:web      # dist/web/index.html (itch.io, Game Jolt, Newgrounds, свой сайт)
npm run build:vkplay   # dist/vkplay/index.html (для iframe VK Play; нужен свой хостинг по https)
npm run pack           # обе сборки + release/web.zip и release/vkplay.zip
```

Каждая сборка это один `index.html` около 590 КБ (310 КБ в zip), пути относительные. На VK Play браузерная игра открывается в iframe по адресу из поля «Ссылка на страницу для отображения в iframe»; регистрация игроков и платежи не подключены (для бесплатной игры без аккаунтов не обязательны).
